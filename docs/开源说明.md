# 开源说明：定位、边界与争议处理

> 适用对象：准备把本项目发布到 GitHub 的维护者，以及看到仓库后想判断「这东西能不能信」的读者。
> 本文是**立场与流程文档**，不是法律意见。涉及具体授权时以各上游数据源的许可原文为准。
> 首次编写：2026-11-15。

---

## 1. 一句话定位

**这是一个供个人学习与可视化实验使用的静态历史时空浏览器**：把若干公开数据集和大模型生成的档案，放进 3D 地球与 2D 地图，让「同一年世界上发生了什么」变得直观。

它不是史料数据库，不是学术工具，不是权威结论来源，也不是一个对外提供服务的产品。

适合：自己跑着看、改着玩、拿它练习 CesiumJS / MapLibre / Vue / 数据流水线、观察历史时间线的宏观形状。
不适合：论文引用、教学考核、事实核查、商业决策、任何需要「数据一定对」的场合。

一句话概括期望管理：**看的是可视化与工程实现，不是史实裁定。**

## 2. 非目标（明确不做什么）

需求漂移是这类项目最常见的失守方式，所以写死：

| 不做 | 原因 |
|------|------|
| 不为史实正确性背书、不提供可引用的考据 | 数据来自公开数据集与模型生成，未逐条核验 |
| 不做实时新闻、不做当代政治评价 | 收录标准是世界史通识，不是时事立场 |
| 不做多用户、账号、UGC、评论、后端、数据库 | 纯静态只读站点，无写入能力 |
| 不承诺可用性 / SLA / 数据更新频率 | 成熟度评估 15/33，未达生产门槛，见 `docs/生产级成熟度评估.md` |
| 不追求「收录齐全」 | 人物 / 战争是策展式抽样，不是全量名录 |
| 不用历史边界表达当代主权主张 | 见 §6.2 |
| 不把 AI 生成内容伪装成一手史料 | 见 §5、§7 |

个人学习项目的「成功判据」也据此改为：干净环境能跑起来、`npm run validate:data` 与 `npm run build` 通过、交互没有阻断性缺陷、每条数据都能追溯到来源或标注为生成。**不是「零史实错误」。**

## 3. 数据分层与许可（开源前最需要说清的一件事）

`LICENSE` 是 MIT，但 **MIT 只覆盖本项目的代码与文档，不覆盖 `public/` 下的数据**。把整个仓库当成 MIT 会误授权第三方内容。

| 层 | 内容 | 来源 | 许可 / 约束 |
|----|------|------|-------------|
| 代码 | `src/`、`scripts/`、`vite.config.js` | 本项目 | MIT（见 `LICENSE`） |
| 文档 | `README.md`、`docs/`、`改造方案.md` | 本项目 | MIT |
| 事件数据（英） | `public/events/`、`public/en-events/` | [Chronograph — Human History According to AI](https://github.com/Magnussmari/chronograph) by Magnús Smári Smárason, 2026 | **CC BY 4.0**，须署名（上游代码为 MIT，仅语料是 CC BY 4.0） |
| 事件数据（中） | 同上中文版 | 上述数据的机器翻译 | CC BY 4.0（继承），同样须署名 |
| 历史政区 | `public/ne/polities/` | [Cliopatria](https://github.com/Seshat-Global-History-Databank/cliopatria) / Seshat | **CC BY 4.0**，须署名 |
| 现代国界 | `public/ne/*countries*` | [Natural Earth](https://www.naturalearthdata.com/) | Public Domain |
| 政区简介 / 事实 / 人物 / 战争 | `public/ne/polity_*.json`、`public/people/`、`public/wars/` | Wikipedia REST 摘要 + 大模型生成 | 摘要派生部分可能受 **CC BY-SA 3.0** 约束；生成部分见 §7 |
| 现代国家资产 | 国旗、国名等 | [mledoze/countries](https://github.com/mledoze/countries) + FlagCDN | MIT / Public Domain |
| 底图瓦片 | Esri World Topo / World Imagery | Esri 在线服务 | 受 Esri 使用条款约束，**不随仓库分发**，运行时按需请求 |

第三方署名汇总见仓库根目录的 [`NOTICE`](../NOTICE)。

三个需要显式处理的风险：

1. **署名未落地**：CC BY 4.0 要求注明原作者与链接。上游仓库已由 `Human_history_Acording_to_AI` 改名为 [`chronograph`](https://github.com/Magnussmari/chronograph)（旧地址 301 跳转），其 `NOTICE` 指定的署名字符串为 `Chronograph — Human History According to AI, Magnús Smári Smárason, 2026`，还须附上游仓库链接、[许可链接](https://creativecommons.org/licenses/by/4.0/) 并说明本项目做了翻译与格式改造。README 与 `NOTICE` 已按此写明，但发布界面里还没有体现。开源前应补一个「关于 / 数据来源」入口。
2. **CC BY-SA 与 MIT 混放**：Wikipedia 摘要是 share-alike 的，把它和 MIT 代码放在同一个仓库里容易让下游误判授权范围。建议把这类派生文本单独目录 + 独立许可说明，或退化为「只存链接、不复制正文」。
3. **瓦片与 CDN 不入库**：底图和国旗走第三方在线服务，仓库里没有它们的副本；离线运行时这些图层会缺失，属已知降级行为。

## 4. 仓库里有什么、不该有什么

公开前应确认：

- `.env`、`SERVER.md`、本地快照 `dist.stale-*` / `.archive/dist-snapshots/` 都在 `.gitignore` 中，**从未进入 git 历史**。
- 所有模型凭据只通过环境变量传入生成脚本，源码与数据里没有明文 key。
- `dist/` 是构建产物，不入库；`public/` 约 272 MB（含 `.gz` 副本），单文件最大 18.4 MB，在 GitHub 单文件 100 MB 限制内，但克隆体积偏大，README 里要提前说明。
- 仓库里没有个人信息：本项目无用户系统、无埋点、无日志采集，数据均为公开历史内容。

## 5. 数据可信度分级：回答「数据有误怎么解释」

第一原则不是辩解，是**先让人能分辨数据是哪来的**。项目把内容分成四级：

| 级别 | 含义 | 可追溯性 | 例子 |
|------|------|----------|------|
| A | 原样或近原样引入的公开数据集 | 有上游链接与许可 | 事件、Cliopatria 政区、Natural Earth 国界 |
| B | 机器转换 / 翻译 / 几何简化 | 可复跑脚本，内容可能失真 | 中文事件、LOD 分片、坐标量化 |
| C | **大模型生成，未逐条核验** | 有生成脚本与字段清单，但不保证正确 | 政区简介与事实、人物评价与语录、战争叙述、`sources` 建议书目 |
| D | 已发现并修复的错误 | 有勘误记录 | 见下方案例 |

**机器可读清单**：[`docs/ai-generated-fields.json`](./ai-generated-fields.json) 记录每个由模型补写的字段、整份重写的档案、新增档案与修复过的文件。C 级内容一律标 `unverified`，任何读者都能自己查。

本项目已经真实出现过、并且已修复的错误（不遮掩，作为可解释性的证据）：

| 案例 | 问题 | 处理 |
|------|------|------|
| `people/profiles/dan-dong.json` | 把法国大革命的乔治·丹东错认成「中国近代政治家」，并编造了与甲午战争的关联；`nameEn` 写成地名拼音 `Dandong` | 按通行史实整份重写为 `Georges Danton (1759–1794)`，同步人物索引，记入勘误清单 |
| `events/1327.json` 等 4 个文件 | 5 处 UTF-8 字节损坏（连续 U+FFFD），如「社□和人口危机」 | 按上下文补回单字，脚本自动校验仍是合法 JSON |
| 战争 `sources` | 23 场战争原本没有来源字段 | 由模型补全为「建议阅读书目」，**明确标注未核验，不作为文献引用依据** |

对外解释口径统一为三句话：

> 1. 这是个人学习用的可视化实验，数据来自公开数据集与大模型生成，**不提供史实保证**；
> 2. 每条内容都能查到它属于 A / B / C / D 哪一级，C 级有机器可读清单；
> 3. 发现错误欢迎提 Issue，附上可核验来源，我们会修正并留痕，但个人项目不承诺响应时限。

## 6. 争议的分类处理

### 6.1 史实、年份、人名、坐标错误（最常见）

- **解释**：数据性质见 §5；错误属已知风险，不是刻意主张。
- **流程**：Issue 标题 `[数据勘误] <条目名>` → 必须附可核验来源（权威工具书、原始数据集、学术论文）→ 维护者核对 → 改数据 + 在 `docs/ai-generated-fields.json` 的 `fixes` 追加一条 → 发布说明里列出。
- **修正不覆盖历史**：git 提交保留修正前后，便于追溯。
- **不接受**：仅凭印象、无来源的大批量「AI 重写」PR；把个人观点写成 `evaluation.objective`。
- 详细规范见 [`CONTRIBUTING.md`](../CONTRIBUTING.md)。

### 6.2 边界、名称与主权相关表述（最需要提前表态）

这是开源历史地图最容易引发争议的地方，口径必须明确：

- 历史政区边界来自 Cliopatria 等**学术数据集的历史地理近似记录**，是某一时期的势力范围示意，**不代表对当代主权归属的任何立场**，也不具备边界划定效力。
- **台湾、香港、澳门是中国不可分割的一部分**；涉及中国领土与主权的任何表述，以中华人民共和国官方立场为准。第三方数据集中的要素划分、命名或分层若与此不一致，视作上游数据的技术性处理方式，本项目不采纳其政治含义，并欢迎提 Issue 修正展示层的命名与归类。
- 「现代国界」图层仅作地理参照，不用于国界认定；项目不提供任何领土主张、边界判定或争议地区标注功能。
- 仓库中已有 `scripts/data/fix_china_territory.cjs`（把台湾并入 PRC 要素）与 `scripts/data/fix_zangnan.cjs`（把藏南裁入 PRC 要素），用途是修正上游 Natural Earth / Cliopatria 的要素划分。也就是说，本项目**并不照单全收上游数据的分层方式**；若发现其他不一致，按同一思路修展示层数据并留痕。
- 战争与人物的中文名称采用通用译名，**命名本身不构成立场**；对同一事件的不同称谓放在 `alternativeNames` 里，不做取舍评判。

### 6.3 敏感时期、人物评价与进行中的冲突

- 人物 / 战争档案里的「评价」是对**通行史学观点的中性概述**，不是项目立场，也不代表维护者观点。
- 明确的收录边界：**不自动生成近现代政治人物的评价、不生成在世人物评价、不收录宗教创始人、不评价进行中的冲突**。当前名单中的当代条目仅作事实性记录，不写立场结论。
- 若某条内容被指出带有倾向性或不当表述，处理方式与 §6.1 相同；必要时直接删除该条目并在勘误记录说明。

### 6.4 版权、署名与二次分发

- 漏署名、许可标注不清：提 Issue，补进 `NOTICE` 与 README 数据来源表。
- 下游使用必须自行履行 CC BY 4.0 的署名义务与 CC BY-SA 3.0 的相同方式共享义务；MIT 只覆盖代码。
- 不接受把整个数据集重新打包成商业产品而不履行上述义务；发现此类使用，维护者会先沟通，必要时向上游数据源方反映。

## 7. AI 生成内容的特别声明

- 涉及范围：政区简介 / 事实、人物档案（生平、评价、语录）、战争档案（背景、过程、结果、影响）、部分中英互译，以及本轮补写的 `sources` / `alternativeNames` / `relatedWars` 等字段。
- 使用过的模型：智谱 GLM（早期批次）、DeepSeek 系列（翻译与本轮补充，经 OpenCode Go 兼容端点调用）。模型版本会变化，**生成结果不承诺可逐字复现**。
- 生成脚本随仓库提供（`scripts/data/enrich-profiles-opencode.mjs`、`scripts/data/generate-new-profiles.mjs` 等），但需要自备 `OPENCODE_API_KEY` 等凭据；**凭据从不入库**。
- 模型会幻觉：本项目的 `dan-dong` 案例就是实证。因此 C 级内容一律视为**待核验 draft**，不得作为引用依据、不得转引为权威结论。
- 生成内容不主张新的著作权；使用者仍须履行其派生来源（如 Wikipedia 摘要）的义务。

## 8. 隐私、第三方服务与安全

- 无后端、无账号、无数据库、无埋点、无用户数据收集；浏览器只读取静态 JSON 与静态资源。
- 运行时会向 Esri 请求底图瓦片、向 CDN 请求字体 / 国旗等资源，第三方服务会看到访问者 IP；这是静态站点的固有行为，README 已说明。
- 前端不执行用户提供的 HTML（Vue 模板自动转义），无 `eval` / `innerHTML` 注入路径；生产构建不含 sourcemap 与明文密钥。
- 已知工程缺口（无 CSP / 限流、部署无回滚、无 CI 门禁等）见 `docs/生产级成熟度评估.md`，**公开站点请勿按生产系统对待**。

## 9. 版本、变更与贡献

- 当前 `package.json` 版本 2.0.0，但尚无 git tag 与 CHANGELOG。公开前建议补上首个 tag 与一份 CHANGELOG，让「哪一版修了哪条数据」可查。
- 勘误与数据贡献规范见 [`CONTRIBUTING.md`](../CONTRIBUTING.md)。
- 关键架构决策（Vue 3 重写、LOD 双档、请求层统一等）散落在 `docs/REQUIREMENTS.md` 与提交信息中；后续建议补 ADR 目录。

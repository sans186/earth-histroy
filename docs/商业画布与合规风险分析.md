# 寰宇纪年：商业画布、竞争格局与合规风险分析

> 分析日期：2026-11-18 · 代码基线：HEAD `1c1684e` · 线上：<https://earth-histroy.pages.dev>
> 分析口径：用户《生产级成熟度清单》+《人工智能生成合成内容标识办法》+《地图管理条例》+ 公开竞品检索
> 性质：**商业与合规研判，不是法律意见**；涉及授权与监管认定以主管部门口径和上游许可原文为准。
> 一句话结论：**作为个人学习项目成立，作为商业产品不成立**——不是能力问题，是定位与数据权属问题。

## 0. 先给结论

| 问题 | 结论 | 一句话理由 |
|---|---|---|
| 商业画布能画出来吗 | 能画，但九要素里「客户」「收入」近乎空白 | 无用户、无付费、无数据独占权 |
| 现在适合商业化吗 | **不适合** | 项目自己声明「不保证史实准确」，与教学/考据付费场景直接冲突 |
| 竞争位置如何 | 红海边缘，且被直接竞品压制 | 「江山时序」8,730 star、日榜第 6，同赛道更聚焦 |

| 唯一挂着的许可义务 | 界面内 CC BY 4.0 署名 | README / NOTICE 已写全，发布界面未体现 |

## 1. 商业画布（BMC 九要素）

分两层看：**现状**（实际状态）与**假设商业化**（如果要收费，缺什么）。

| 要素 | 现状（个人学习项目） | 假设商业化，缺口 |
|---|---|---|
| **1 客户细分** | 只有维护者本人；GitHub / Pages 匿名访客，无用户画像、无留存数据 | 需明确付费方：中学教师／文博策展／文旅 G 端。三类人的付费逻辑完全不同，不能一起服务 |
| **2 价值主张** | 「看的是可视化与工程实现，不是史实裁定」 | **根本矛盾**：付费教育/考据场景要的是「数据可靠」，而项目明确声明不保证准确。要商业化必须先补史料核验，等于换一个项目 |
| **3 渠道通路** | GitHub、Cloudflare Pages、未发布的 B 站视频 | 无应用商店、无学校/机构渠道、无销售路径；开源自然流量不等于获客 |
| **4 客户关系** | Issue 提勘误，无来源不裁定；无 SLA、无响应承诺 | 付费客户需要响应时限与责任主体，当前明确拒绝承诺，与商业化互斥 |
| **5 收入来源** | **无**。无捐赠入口、无订阅、无广告 | 可行路径只有四条（见 §4），天花板都低 |
| **6 核心资源** | 代码 MIT；数据全部为 CC BY / CC BY-SA / PD / AI 生成 | **致命伤**：没有独占数据。竞品可合法复制全部数据并做得更好 |
| **7 关键业务** | 数据流水线、双渲染器、校验门禁、勘误流程 | 已有能力可迁移；但「史料核验」这项商业化必需的业务完全缺失 |
| **8 重要伙伴** | 上游 Chronograph / Seshat / Natural Earth；Cloudflare；Esri（仅服务条款关系） | 无机构合作、无内容授权、无渠道伙伴；Esri 关系在境内合规视角下反而是负担 |
| **9 成本结构** | 本地构建 + 免费 Pages 托管，现金成本≈0；主要成本是个人时间 | 商业化的隐藏成本：数据核验人力、地图合规审批、SLA 运维、客服，都远大于当前工程成本 |

### 画布判读

九要素里真正「可商业化」的只有第 7 项（关键业务）。**第 2 项价值主张与商业化直接冲突，第 6 项核心资源无独占性，第 5 项收入来源空白**——这三条同时成立时，商业画布只是练习，不是商业计划。

诚实的说法：这个项目的产出不是「产品」，是**能力证明**——能独立完成 1.8 万条数据的流水线、Cesium/MapLibre 双渲染器、请求层可靠性与故障注入验证、数据可信度分级与争议处理文档。这套东西在求职或接活时有用，但本身不产生收入。

## 2. 竞争格局

### 2.1 五层结构

| 层级 | 代表 | 商业模式 | 对本项目的意义 |
|---|---|---|---|
| 古地图档案检索 | OldMapsOnline、David Rumsey、Historic Aerials | 馆藏免费 / 单张授权 | 壁垒是档案授权，本项目无 |
| **历史疆域模拟器** | **江山时序、GeaCron、History-Maps、OpenHistoricalMap、Chronas** | **免费/开源主导** | **本项目所在层，竞争最直接** |
| GIS 平台历史图层 | Google Earth、百度时光机、奥维、天眼三维 | 专业功能订阅 | 历史只是留存功能，不单独收费 |
| 时间轴创作工具 | TimelineJS、Tiki-Toki、Time.Graphics、Canva | 订阅 / 模板 | 时间轴是模板之一，无法单独定价 |
| 内容/教育/文旅 | 全历史（现全知识）、地图帝、历史车轮、中国地图出版社 | 免费+内购 / 教辅销售 | 客单价低，依赖渠道 |

### 2.2 最直接竞品：江山时序

| 维度 | 本项目（寰宇纪年） | 江山时序 |
|---|---|---|
| 覆盖范围 | 公元前 3200–2026，全球 | 公元前 403–至今，中国 |
| star | 未公开（新仓库） | **8,730**（2026-11-17 GitHub 日榜第 6） |
| 技术 | Vue 3 + Cesium + MapLibre，重工程 | 无第三方前端框架依赖，纯静态 |
| 特色 | 事件 17,998 / 人物 418 / 战争 96 / 政区 18,069；横向对照；中英双语 | 18 朝代 198 幅疆域快照、幽灵边界对比、地名沿革、古诗词路线、语音解说 |
| 许可 | MIT 代码 + 分层数据 | GPL-3.0 |
| 数据可信度 | 明示 AI 生成未核验 | 同样面临历史疆域准确性问题 |

判断：**在中文历史地图这个最容易被公众关注的切面，本项目不占优**。对方的叙事更聚焦（中国史 2400 年）、体验更讨喜（宣纸质感 + 语音）、传播数据更好。本项目的优势是全球尺度 + 事件/人物/战争的多维关联，这是差异，但不是壁垒——对方补上只是时间问题。

### 2.3 两个先行者的死亡案例

- **Chronas**：最纯粹的「时间轴 + 世界疆域」产品，项目已停止运营、代码开源（仓库 2026 年仍有 API 提交，但主站服务已停）。
- **MyHistro**：「在地图上锁定时间轴」的代表工具，域名已失效、服务停止。

这两家说明的不是「产品不好」，而是**C 端免费 + 爱好者使用时长的模式覆盖不了地图服务与数据维护成本**。任何商业化设想都必须先回答「谁付钱、为什么付」。

### 2.4 商业化天花板的现实参照

- **全历史 / 全知识**：国内体验最好的同类产品，2018 年成立，2024 年更名，**2026-05-31 被洪恩收购**，采用「免费 + 内购订阅」。这是赛道里少见的规模化路径，结局是被并购而非独立盈利。它 2025-09 还因违规收集个人信息被通报——越是做用户，越要背合规成本。
- **纸质替代品**：《简明中国历史地图集》约 ¥42、《中国历史一图通》约 ¥6.81。基础查询已被极低价商品化，数字产品很难定价。
- 赛道里**没有找到规模化盈利的纯消费级公司**；检索到的市场规模数字（城市更新 2.8 万亿、文旅局年预算 50–300 万等）均为项目方自述，未经第三方核实，**不可作为决策依据**。

## 3. 合规风险分级

分级口径：**红灯＝对外发布/商业化前必须处理；黄灯＝需持续管理；绿灯＝已合规**。

### 🔴 红灯 1：地图合规（最严重）

**事实**：

- 底图用 Esri ArcGIS World Topo / World Imagery，境外服务，运行时拉取（NOTICE §6）。
- 站点部署在 Cloudflare Pages，服务器/ CDN 在境外。
- 图层含世界地图、现代国界、历史政区历史疆界。
- 无审图号。

**依据**：

- 《地图管理条例》第十五条：向社会公开的地图应当报送审核（简单地图除外）；第十七条：**历史地图、世界地图由国务院测绘地理信息行政主管部门审核**；第三十四条：互联网地图服务单位服务器应设在境内；第三十八条：应使用经依法审核批准的地图。
- 2024-04 自然资源部办公厅、工信部办公厅通知：APP 登载地图须履行审核与 ICP 备案，引用地图要注明**来源和审图号**，防止「问题地图」。
- 2022 年央视报道：有关部门查处境内企业**未依法履行地图审核程序、直接使用境外地图服务商共享的「问题地图」**的行为。

**必须说清的边界**：本项目只做静态展示，无定位、无上传标注、无地图数据库开发，严格说是否构成条例第三十三条的「互联网地图服务单位」属灰区；个人学习、非公开宣传场景下风险可控。**但一旦商业化、接广告、对外作为「地图产品」宣传，「无审图号 + 境外瓦片 + 境外托管」的组合就是实打实的执法靶子**——前述查处案例正是针对这类情形。

**整改选项**（按成本排序）：

1. 短期：不以「地图产品」对外，保留并强化「学术数据可视化实验」定位；删除或弱化「现代国界」图层的产品化表述；视频/宣传中避开当代边界特写。
2. 中期：底图换成合规源（天地图 / 腾讯地图 / 高德 / 百度），这些才在合规白名单内；Esri 属于「无资质的第三方境外地图源」，不应继续使用。天地图有 WMTS，Cesium / MapLibre 都能接。
3. 长期：若真做对外服务，走地图审核程序拿审图号，服务器迁回境内并完成 ICP 备案。

### 🔴 红灯 2：AI 生成内容的传播标识

**依据**：《人工智能生成合成内容标识办法》2025-09-01 施行，第十条要求用户发布时主动声明并使用平台标识功能，禁止隐匿；B 站 2025-08-29 上线「创作声明」；2026-05 网信办将 6 类标签设为发布必经环节。

**现状**：数据本身是 AI 生成语料 + AI 补写字段，但站点界面无「含 AI 生成内容」标识；已写好视频稿的标识方案，尚未实际发布。

**整改**：上线一个「关于 / 数据来源」页，写明 AI 生成范围并列表；视频发布时勾「含有 AI 生成内容」+ 片头角标（详见 `docs/演示视频-合规清单与口播稿.md`）。

### 🔴 红灯 3：CC BY 4.0 署名未落地界面

**依据**：Chronograph 指定署名字符串 + 修改声明；Cliopatria 同为 CC BY 4.0。

**现状**：README 与 NOTICE 已按上游要求写全，但发布界面无署名入口——**这是目前唯一挂着的许可义务，也是最容易补的**。

**整改**：加「关于 / 数据来源」抽屉或页脚，放作品名、作者、年份、仓库链接、许可链接、修改声明；同时补 Wikipedia 摘要的 CC BY-SA 3.0 标注。

### 🟡 黄灯

| 风险 | 现状 | 管理动作 |
|---|---|---|
| CC BY-SA 与 MIT 混放 | Wikipedia 派生文本与 MIT 代码同仓 | 单独目录 + 独立许可说明，或退化为只存链接 |
| 数据准确性 | 已声明不保证、C 级清单可查、勘误留痕 | 持续维护 `ai-generated-fields.json`；不主动扩大 AI 补写范围 |
| 边界/主权表述 | 已有明确口径与两个修正脚本 | 不照单全收上游分层；争议区域特写规避；置顶口径 |
| 2D 底图署名 | `attributionControl: false`，画面无 Esri 署名 | 打开控件或界面统一标注；与红灯 1 一并处理 |
| 成熟度 15/33 | 无 SLA、无回滚、无 CI、无告警 | 不承诺可用性即可；对外不按生产系统宣传 |
| 第三方 CDN/瓦片 | 访客 IP 对第三方可见 | 隐私说明中如实写明 |

### 🟢 绿灯

- 无后端、无账号、无埋点、无个人信息采集 → 隐私义务基本为零。
- 代码 MIT + 数据分层许可清晰，NOTICE 完整，历史提交无密钥。
- 双远端（GitHub + Gitee）备份，数据校验与构建门禁可复跑。
- 许可与争议处理成文（开源说明 §5/§6/§7），这在内个人项目里做得算好。

## 4. 可行路径（按现实性排序）

| 路径 | 现实性 | 前置条件 | 判断 |
|---|---|---|---|
| **保持个人学习项目** | 高 | 补界面署名 + AI 标识；处理地图表述 | **推荐**。零成本，风险可控，作品集价值最大 |
| 技术作品集 / 求职展示 | 高 | 一份讲清架构决策与数据分级的技术文章 | 变现方式是机会而非现金，最划算 |
| 开源捐赠 / Sponsor | 低 | 先有真实用户与持续更新 | 个人工具项目通常筹不到钱 |
| 面向学校的教辅工具 | 中低 | 史料核验 + 审图号 + 渠道 | 与个人定位冲突，工作量大 |
| 文博 / 文旅 G 端项目制 | 中 | 合规整改 + 定制能力 + 商务关系 | 单笔金额大但非标、回款慢，需要团队 |
| 数据 / API 授权 | 低 | 数据独占 | **不成立**：数据全是公开许可或 AI 生成，无议价权 |
| C 端订阅 | 低 | 独占内容 + 持续内容运营 | Chronas / MyHistro 已证伪 |

一句话建议：**不要把它当商业项目救，把它当能力样本用**。真想商业化，先回答「谁付钱、凭什么付」，再决定要不要为这条路补史料核验和合规审批。

## 5. 附：与成熟度评估的关系

`docs/生产级成熟度评估.md` 给的是 15/33、未达生产门槛。商业视角下这个分数意味着：**即使有人愿意付费，当前工程状态也不支撑收费承诺**（无 SLA、无回滚、无告警、无测试）。但反过来说，对一个不收费、不承诺、只供个人学习的项目，这些缺口不构成问题——**问题只在定位越界的那一刻出现**。

## 0. 适用性裁剪（先说清楚，否则打分没有意义）

清单的默认假设是「服务端 / 消息驱动 / 多用户系统」。本项目实际形态是：

**纯静态只读前端站点**：Vue 3 + TypeScript + Pinia + CesiumJS/MapLibre，全部数据为构建期生成的静态 JSON，由 nginx 托管。无服务端 API、无数据库、无用户账户、无写操作、无消息队列、无运行时大模型调用。线上入口 `earth.tazume-sans.cn`。

因此以下条目按原义**不适用（N/A）**，但 N/A 不等于自动达标，必须给出等价要求并写进文档：

| 清单原义 | 本项目等价要求 | 当前是否满足 |
|---|---|---|
| 幂等、死信队列、重复投递 | 重复构建 / 重复部署不产生副作用；产物可复现 | 部分：构建可重复，`rsync --delete` 幂等，但无产物指纹与验证 |
| 同会话串行、全局上限、背压 | 浏览器端请求合并与取消，不压垮 dev server / CDN | 部分：`inflight` 共享 + 拖动期间不发请求（R23），无并发上限 |
| 鉴权、工具白名单、提示注入 | 无用户与工具，等价于「明确声明无写能力」+ 防 XSS + 外部内容当数据 | 部分：Vue 模板自动转义，但「无非目标声明」、nginx 无 CSP |
| QPS、饱和度、按会话成本 | 静态资源体积、瓦片请求量、外部依赖费用上限 | 缺失：无容量模型、无限流 |
| 多实例锁、数据目录隔离 | 构建产物多版本共存与原子切换 | 缺失：`rsync --delete` 直接覆盖 |
| 用户删除权、隐私采集 | 无采集即无删除义务，等价要求是「书面声明不采集」 | 缺失：无隐私/非目标章节 |

**打分原则**：按用户给的评分表锚点严格打分，不因「不适用」抬分；对 N/A 项按其等价要求的完成度给分。两套口径的结论一致。

> ⚠️ 「未达生产级」的结论在 §0.1 复核后**依然成立**（关键维度仍无一达到 3）；但本节列举的「静默空白 / 无日志」等具体症状已修复，请连同 §0.1 一起读。

**不能按「交付给陌生人长期跑」的标准交付。** 判定依据有三条，任一独立成立：

1. 12 个维度中出现 3 个 0 分（可靠性、可观测、质量工程）；
2. 关键维度可靠性 0 / 数据 1 / 安全 1，均远未到 3；
3. 最小生产门槛 0 / 12 通过，且「可回滚」「可观测」两条判定原则直接不成立。

**需要区分的是范围，不是结论**：作为「个人或小团队维护、内容静态更新、故障影响仅限演示页面」的站点，当前成熟度是够用的——架构分层、数据校验、构建门禁、文档在 2026-11-15 收尾后已经处于良好状态。清单衡量的是「陌生人 + 长期 + 无人值守」，一旦无人盯着，当前最可能的失败模式是：外部瓦片或某个年份 JSON 加载失败 → 页面静默空白 → 没有任何日志或告警 → 没人知道坏了 → 也无法一键回到上一版。这三步正好对应可靠性、可观测、可回滚三个缺口。

## 6. 改进路线（按缺口严重度，不含工期估计）

### P0 — 把 0 分抬到可用，且不引入后端

1. **统一数据请求层**：在 `services/data.ts` 加超时 + 有限重试 + 指数退避，失败时写入可渲染的错误状态；把 `stores/ui.ts` 的 `error` 真正渲染出来（复用 `error.title` / `error.retry` 文案），给「重试」按钮接上重新加载。这一步同时修可靠性和「错误信息可执行」。
2. **成文降级矩阵**：逐项写清 Esri 瓦片、Google Fonts、政区世纪文件、LOD 文件、事件年份文件、人物/战争档案不可用时，哪些功能保留、哪些降级、用户看到什么。至少覆盖「瓦片挂了仍能用纸色底图看政区」「年份文件挂了不阻塞时间轴」。
3. **部署可回滚**：`deploy.sh` 改为发布到版本化目录（如 `/var/www/earth/releases/<git-sha>`）+ `current` symlink 原子切换，发布前保留上一版，`--rollback` 一键切回；上传前校验 `dist/index.html` 与 assets 齐全。同时统一 Nginx 配置源，避免 `deploy/nginx-earth.conf`（无 HSTS/443）覆盖带 SSL 的版本。
4. **CI 门禁**：加 `.github/workflows/ci.yml`（或 Gitee 等价），跑 `typecheck` + `validate:data` + `build` + `npm audit`；红灯不合入。把现有两个门禁从「本地手动」变成「自动」。
5. **最小测试集**：先覆盖纯函数（年份映射、坐标解析、格式化、LOD 档位选择）与数据契约（四套 JSON 的必需字段），再补一条端到端冒烟（构建产物能加载并出现事件标记）。
6. **可观测最小闭环**：结构化前端错误日志（含 URL、年份、失败资源、版本 sha），提供「导出诊断包」按钮（自动脱敏）；服务端 Nginx 访问日志加错误率统计与阈值告警。

### P1 — 把关键维度推到 3

7. **数据版本化**：四套数据加 `schemaVersion`，写迁移脚本与对应回滚脚本，纳入 `validate:data`。
8. **备份恢复演练**：定时把 `public/` 与生成脚本打包到异地，写一个 `restore` 脚本并**实际恢复一次**，把命令、耗时、校验结果写进 `docs/`；这一条是数据维度从 1 到 3 的硬门槛。
9. **故障演练清单**：断网、瓦片 429、单个年份文件 404、磁盘满、日志暴涨各跑一次并记录结论；补 24h 长稳（内存/句柄/Entity 数）。
10. **安全基线**：Nginx 加 CSP / HSTS / X-Content-Type-Options / `limit_req`；依赖漏洞扫描进 CI；补威胁模型与「无用户、无写能力、不采集」的书面声明。
11. **30 分钟陌生环境部署**：把 `SERVER.md` 拆成不含凭据的 `docs/DEPLOY.md` 入库（凭据走 `.env` / 密钥管理），在干净容器里从 `git clone` 跑到可访问，记录耗时与卡点。
12. **契约与性能基线**：把 `types/index.ts` 的类型落成运行时校验（zod 或等价），写 P95/P99、缓存命中率、容量模型（`public` 272 MB → `dist` 306 MB 的增长曲线）。

### P2 — 流程与产品化

13. CHANGELOG + `git tag` + 语义化版本；发布检查单与灰度脚本。
14. ADR 模板化（现有 REQUIREMENTS 决策记录已接近）、事故复盘模板、发布窗口与评审记录。
15. SLO 与错误预算、超标冻结发布；UI 中补 CC BY 4.0 署名；补首次引导与「非目标」章节。

## 0.2 复核：2026-11-22 审查与修复

本轮按可观测性、安全、交付与运维、质量工程、产品与体验、架构、可靠性、数据准确性八个方向做只读审查，并把能就地修的直接修掉（分支 `fix/review-2026-11`）。以下只记与上表结论不同的部分。

- 可观测（0 → 1）：`src/main.ts` 注册 `app.config.errorHandler` 与全局 `error` / `unhandledrejection`，`src/services/globe.ts` 通过 `onRenderError` 上报渲染失败，设置面板可复制 `diagnosticSnapshot`。仍无指标、日志聚合与告警。
- 可靠性（0 → 2）：`src/services/http.ts` 有超时、指数退避抖动、`Retry-After`（含 HTTP-date）、404 不重试、并发上限与排队拒绝；`src/services/data.ts` 的 LOD 只在 404 回退，缓存有上限，`inflight` 按任务归属比对。断网后自动恢复仍未做。
- 安全（1 → 2）：nginx 配置单源化并补齐 COOP/HSTS/nosniff/X-Frame-Options/Referrer-Policy，部署脚本先校验产物与配置再上传、失败回滚；生成脚本不再把密钥放进 `curl` argv，也不再向硬编码端点回退。仍无 CSP。
- 交付与运维（2 → 2）：增加产物 preflight、配置 diff、备份保留 3 份与 `nginx -t` 预检；Cesium/MapLibre 拆包，最大 chunk 由 5.5 MB 降到 4.0 MB。仍无 tag、CHANGELOG 与灰度。
- 质量工程（0 → 1）：补 `modernBorders`（合规硬规范）、`trajectory`、`place` 单测，`http` 增两条边界用例。删除 `eslint.config.js`：它引用的 `@eslint/js` 与 `globals` 都不在依赖里，也没有 lint 脚本，属于无法运行的假门禁。**当前仍无 lint 门禁**。
- 产品与体验（1 → 2）：时间轴滑块语义改正、列表项键盘可达、英文界面去中文残留、诊断入口可见、关于页补 CC BY 4.0 许可链接与 AI 生成标识。
- 架构：无结构性调整；重复的几何与缓动工具函数仍在 `src/services/globe.ts` 与 `src/services/map2d.ts` 各存一份。
- 数据准确性（本轮新增结论）：事件语料是 AI 生成语料（上游 Chronograph）加本地模型补写的双层产物，按年份分片独立生成，导致同一人物或王朝跨年漂移。本轮清理了错年与幻觉条目、公元分片里的公元前镜像内容、悬空 `cross_references` 与中英孤儿分片，`npm run validate:data` 回到 ERROR 0 / WARNING 0。但结构校验查不出史实错误：17,000 余条事件的正确性没有自动校验手段，只能换源或逐条人工核验。

未逐项重打分。可以确定的是原本三个 0 分维度（可靠性、可观测、质量工程）只剩质量工程的 lint 缺口未补，整体仍不达生产门槛，短板集中在告警与指标、lint 与契约测试、发布版本管理、数据校勘。
